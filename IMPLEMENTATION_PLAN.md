Two facts found while verifying class names that the port has to carry (both are new relative to `locked-decisions.md`):

- **`pulumi_aws.ssm.Parameter.value` is always a secret output** (registry, ssm/parameter: "always marked sensitive in preview output"). So LOCKED-1's "there are no secret values for it to protect" is true of the *inputs* and false of the *checkpoint*: after the first `up`, three public strings (bucket name, distribution id, site URL) sit passphrase-encrypted in `.pulumi/stacks/static-site/<env>.json`. The decision stands (passphrase, no KMS); the runbook wording becomes "protects three values the provider marks secret by schema, none of which is sensitive". `plan.yml` needs the repository secret for **every** preview, applied or not: the CLI verifies the passphrase against the committed `encryptionsalt` when it builds the secrets manager, before any value is touched (measured 2026-09-16 on 3.263.0: `preview` on a never-applied stack without the variable fails with `passphrase must be set with PULUMI_CONFIG_PASSPHRASE`; §6). `insecure_value` was considered and rejected: it only changes what the preview shows, the `value` output stays schema-secret in the checkpoint, and the passphrase is needed regardless (docs/PLAN_CRITIQUE_2026-09-16.md F23).
- **Pulumi autonames.** Every resource whose name is a contract — the deploy role, its inline policy, the SSM parameters, the CI roles, the boundary policy, the buckets, the log group, the function, the OAC, the delivery names, the cache/headers policy names — must pass `name=`/`bucket=` explicitly or Pulumi appends a random suffix and the deploy contract (DEPLOY_CONTRACT.md:56-88) and the bootstrap grants (oidc.tf:289-350) break at first apply. §3 marks each; a pytest over the offline preview asserts it (§4 Phase 2). Four of those names embed the `random_id` hex and are therefore *unknown* at preview (the JSON carries the sentinel `04da6b54-80e4-46f7-96ec-b56ff0331ba9`), so the test tells "explicit but unknown" from "autonamed" by `propertyDependencies`, not by pattern — Phase 2 item 7 says how (measured 2026-09-16).

## 3. Resource mapping

Class names verified today against `pulumi.com/registry/packages/aws` (v7.46.0 pages) and `packages/random` (v4.21.1). Module listings were fetched for `aws`, `aws.s3`, `aws.cloudfront`, `aws.cloudwatch`, `aws.iam`, `aws.acm`; individual pages for `s3.Bucket`, `s3.BucketV2` (deprecated in favour of `s3.Bucket`), `s3.BucketObjectv2`, `cloudfront.Distribution`, `cloudwatch.LogDelivery`, `ssm.Parameter`, `route53.Record`, `Provider`, `get_default_tags`, `random.RandomId`, and the 7.0 migration guide (the `…V2 → …` renames). **Zero class names unverified.** Nested argument names (e.g. `security_headers_config.content_security_policy.override`) were not checked one by one; `mypy --strict` against the shipped stubs in Phase 2 is the check that catches a wrong one, and it is listed in §7.

Global semantic differences that apply to every row:

- **Naming:** Pulumi autonames; pass `name=`/`bucket=` wherever the Terraform resource set one. Rows marked **N**.
- **Providers:** `provider = aws.us_east_1` → `pulumi.ResourceOptions(provider=us_east_1)`; the component takes both `aws.Provider` objects as constructor arguments (mirror of `configuration_aliases`, versions.tf:30). Rows marked **UE1** use the us-east-1 provider.
- **`count`/`for_each`** → Python `if`/`for`; keys become part of the Pulumi resource name (`f"{name}-{key}"`).
- **`depends_on`** → `ResourceOptions(depends_on=[...])`. **`ignore_changes`** → `ResourceOptions(ignore_changes=[...])`. **`prevent_destroy`** → `protect=True` (weaker: `pulumi state unprotect` removes it with no source edit — cross-cutting finding 4; §4 Phase 1 and TEARDOWN §8 say so). **`create_before_destroy = true`** → Pulumi's default replacement order (create-then-delete); state it as "default, not set" rather than passing `delete_before_replace=False`.
- **`aws_iam_policy_document` data sources** → `json.dumps` of a dict built in `documents.py`, not `aws.iam.get_policy_document`. Reason: no provider invoke, so the builders are pure functions a unit test can call with placeholder ARNs, and the size check at oidc.tf:3116-3134 becomes `sum(len(re.sub(r"\s", "", doc)) for doc in the three inline documents of one apply role) < 9000` in a unit test (the user memory note about measuring without whitespace applies). SIDs are copied verbatim so docs/TEARDOWN.md §5.4-5.5 cross-references survive (LOCKED-5).
- **What is known at preview, and where each assertion therefore lives.** Anything derived from the `random_id` hex (the bucket name and the OAC, function and log-group names built from it) or from a resource ARN or id (every `documents.py` output that embeds one — the site bucket policy, the deploy role's inline policy — and every `*_id` wiring input) is a single unknown at preview: the JSON carries the sentinel `04da6b54-80e4-46f7-96ec-b56ff0331ba9`, and a CrossGuard policy that reads it is *skipped* with `can't run policy '<name>' … can't be known during preview` (measured 2026-09-16; LOCKED-3 treats that line as failure). So: document **contents** are asserted in `tests/unit/test_documents.py` over the pure builders; the preview asserts **existence and wiring** through `steps[].newState.propertyDependencies`, which lists the URNs each input depends on (the bucket's `bucket` → the `RandomId`; the distribution's `defaultCacheBehavior` → the `default` cache and headers policies and the function; the role policy's `role` → the role); and trust policies, names that carry no hex, types, counts and every static argument are asserted directly. A partially-unknown object is readable leaf by leaf — `defaultCacheBehavior.functionAssociations[0].eventType` is known while its `functionArn` is not.
- **Property names are the provider's camelCase names** in both `pulumi preview --json` (`steps[].newState.inputs`) and CrossGuard `args.props`: `maxSessionDuration`, `assumeRolePolicy`, `retentionInDays`, `securityHeadersConfig.contentSecurityPolicy.override`, `tagsAll`. The Python constructor arguments are snake_case; nothing else is. `tagsAll` is the provider-merged `default_tags` and is present on every taggable resource at preview, which is what `policy/posture/tags.py` reads.
- **Component construction.** `StaticSiteArgs` fields are plain `str`/`bool`/`int`, never `Input[...]`: every value is known at construction (config values, the stack name, one invoke result), which is what lets `validation.py` and `naming.py` stay pure and the offline preview stay invoke-free. The two `aws.Provider` objects are explicit constructor arguments because a `ResourceOptions.providers` map holds one provider per package and the component needs two of the same package. Every child resource passes `opts=pulumi.ResourceOptions(parent=self, provider=<the one it needs>, …)` — a child without `parent=self` is a top-level resource that `--target`, URN nesting and the "N children of the component" count all miss — and the component ends with `self.register_outputs({...})` so the CLI does not report it as still creating.
- **`lifecycle { precondition }` / `check`** → `raise` in the component (preconditions) or `pulumi.log.warn` (the two `check` blocks, oidc.tf:550-566 and 2656-2666, which are warnings in Terraform too).
- **`default_tags`** → `aws.Provider(default_tags=aws.ProviderDefaultTagsArgs(tags={...}))` on both providers; `ManagedBy = "pulumi"` (cross-cutting finding 2).

## 5. Makefile design

Same two halves as Makefile:12-15: checks (AWS-free) above the line, AWS verbs below. `SHELL := /usr/bin/env bash -euo pipefail` and `.SHELLFLAGS` both (Makefile:17-46). Pins at the top: `PULUMI_VERSION := $(shell cat .pulumi.version)`, `UV_VERSION := $(shell sed -n 's/^required-version = "==\(.*\)"$$/\1/p' pyproject.toml)` (the pin lives in `pyproject.toml` `[tool.uv] required-version`; the Makefile reads it the way it reads `.pulumi.version`), `TRIVY_VERSION := 0.74.0`, `ZIZMOR_VERSION := 1.30.1`, `RUNNER_IMAGE := ubuntu-24.04`. ruff/mypy/pytest versions are `uv.lock`'s; every Python invocation is `uv run --locked --all-packages`: `--locked` fails on a lock that does not match any `pyproject.toml` in the workspace (`--frozen` would use the stale lock silently and cancel `UV_LOCKED` — §2), `--all-packages` keeps every member's closure in the shared `.venv` so `mypy --strict envs` finds `pulumi_aws` even after an operator's plain `uv sync` pruned it (§1). No recipe runs `pulumi login`: each one that touches a backend sets `PULUMI_BACKEND_URL` inline, so a stale login or a stray export in the operator's shell cannot redirect it (§4 Phase 1).

## 8. Explicit non-goals

Taken from the Terraform README's own tradeoffs (README.md:414-528) and the locked decisions; each is a thing the port deliberately does not do.

- **No standing environment, no live URL, no drift detection, nothing on call** (README.md:3-12). Every stack is applied, verified and destroyed inside the hour; `e2e.yml`'s weekly `schedule` stays commented out (e2e.yml:191-200), so the proof is only as recent as the last dispatch.
- **`prod` is verified by hand and is outside `e2e.yml`** (README.md:502-505); the workflow takes no environment input.
- **The custom-domain path is plan-verified only** — the `managed-cert` and `supplied-cert` offline variants are the whole of its verification, never an apply, in CI or by hand (README.md:512-516; TEARDOWN §7 kept "unverified").
- **One AWS account, isolation by naming, not by account boundary** (README.md:414-456; D-1 — the account the Terraform repository used, now empty): the fourteen account-wide statements in `apply_infrastructure` port as they are; no attempt to narrow the untaggable CloudFront policy/OAC surface; the two 20-per-account quotas are shared with whatever else is in the account.
- **No Pulumi Cloud**, no `PULUMI_ACCESS_TOKEN`, no KMS key, no DynamoDB (LOCKED-1). The durable-deployment answers — `change-secrets-provider awskms://`, a CMK on the state bucket, separate accounts — are written where the Terraform repository writes theirs (state.tf:106-126; README.md:455-456) and not built.
- **No `set_mocks` unit tier** (LOCKED-3): optional and not built in this port; the slot is `tests/mocks/` if someone wants it, never a required check.
- **No Pulumi ESC / `pulumi env`** for configuration or secrets: ESC is a Pulumi Cloud service (LOCKED-1 rejects the SaaS dependency), and the whole configuration is ten committed non-secret values per environment (nine identity values plus `forceDestroy`) plus one passphrase in a repository secret.
- **No Automation API**, for e2e or anywhere: the workflows and the Makefile share the CLI's commands as their interface, exactly as the Terraform repository's do (Makefile:1-15), and moving orchestration into a Python program would put the apply/destroy sequence somewhere `zizmor`, `actionlint` and `audit-policy` cannot see it.
- **No third-party IaC scanner** and no attempt to make Checkov/Trivy/KICS/Snyk read Pulumi Python (LOCKED-4). `trivy` stays for `uv.lock` SCA only, advisory.
- **No provider-lock-refresh workflow and no `PROVIDER_LOCK_TOKEN`** (LOCKED-4); `.pulumi.version` and `.python-version` move only by a reviewed PR.
- **No lifecycle rule or versioning on the site bucket** (README.md:518-523); no S3 access logging or WAF on the distribution (cloudfront.tf:304-340; s3.tf:40-52).
- **No AWS credential outside OIDC**, anywhere, ever (docs/BOOTSTRAP.md:815-816); the bootstrap is a human with an exported session and deliberately not CI.
- **No Terraform-state migration, no import of the Terraform repository's resources, no shared bootstrap**: the two repositories are independent from zero (LOCKED-2), the Terraform tree is read-only for this work, and the `isai2105-local-operator` mirror is not extended to the Pulumi roles (cross-cutting finding 8).
- **Not a change to the deploy contract**: `react-cloudfront-app` sees the same role name, subject, parameters, CSP and command sequence (cross-cutting finding 1); the only thing it could observe would be a different account id, and D-1 keeps the account the Terraform repository used, so it observes nothing (DEPLOY_CONTRACT.md:36-41 makes the id a variable on its side regardless).
- **No `make` target for actionlint or `pr-title`** (README.md:383-388) — the same two required checks with no local equivalent.
- **No OpenTofu/BSL discussion** (README.md:525-528): Pulumi is Apache-2.0 and the tradeoff entry is simply dropped rather than rewritten.
